Technology　 /　 Proposed architecture

Behind an indoor route.

Routing Positioning Kiosk ID Door access

Shared route calculation. ABC-chan uses the same campus maps whether you start at the entrance kiosk or on your phone.

  1. Mobile app or kiosk → ABC-chanThe traveller confirms a Wi-Fi position estimate in the app. The kiosk uses its fixed location at the main entrance.
  2. ABC-chan → Backend API → Routing engineABC-chan sends the start, destination and route preferences to the same API and routing engine from either interface.
  3. Campus database → Routing engineIndoor maps supply rooms, paths and accessible connections.
  4. Routing engine → API → ABC-chanThe app gives turn-by-turn guidance. The kiosk presents directions on screen and through its speakers.

Indoor positioning. The mobile app estimates the traveller’s floor and starting point from Wi-Fi. The entrance kiosk uses its configured position.

  1. Wi-Fi access points → Indoor positioningCampus signal measurements support a building, floor and position estimate.
  2. Indoor positioning → Backend APIThe position estimate becomes a suggested starting point.
  3. Backend API → Mobile appThe traveller confirms or corrects the marker before routing.

Optional kiosk identification. A college ID tap could personalise the greeting. Visitors can start as guests. A separate NFC reader handles door access.

  1. College ID reader → KioskStudents and staff could identify themselves with a compatible college ID. Guests can use the kiosk anonymously.
  2. Kiosk → ABC-chanThe assistant could greet identified users. Both session types use the same entrance start and route services.

Authorised door access. The college access system makes a separate decision at the door.

  1. Mobile application → NFC readerA compatible phone presents a valid college credential.
  2. NFC reader → Electronic door systemThe existing system checks permissions and releases the door only when authorised.

Campus deployment

What the system needs

Integration choices depend on the college’s infrastructure and policies.

Positioning and floor detection

Wi-Fi coverage and overlapping signals can affect accuracy, especially between floors. The design asks users to confirm the estimate before continuing.

Maps and accessibility data

Routes need current floor plans, connected paths, room records and verified details for lifts, ramps and accessible entrances.

Kiosk installation and college IDs

The kiosk would use the surveyed entrance position as its route origin. Personalised greetings would require a compatible card reader and college-approved identity handling. The NFC readers at electronic doors handle access permissions.

Hardware and authorisation

NFC access needs a compatible device, campus readers and approved credentials. The college retains control of access permissions.
