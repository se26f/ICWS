System architecture

A connected path from campus signals to guidance.

This is a proposed architecture. Each connection depends on campus mapping, network, positioning, and access-control integration.

Campus inputs

Signal

Wi-Fi access points

Provide signals that may support indoor position estimates.

Access

NFC readers

Read authorised user credentials at compatible electronic doors.

Access control

Electronic door system

Applies the college's own access permissions and unlock decisions.

ICWS services

Positioning

Indoor positioning

Estimates the user's building, floor, and starting point from available signals; asks the user to confirm.

Campus data

Indoor maps & database

Stores proposed room, facility, service, floor-map, and route-network information.

Service layer

Backend API

Connects the mobile application to approved campus data and route services.

Routing

Route calculation

Finds a route between confirmed locations and accounts for floor transitions and accessibility preferences.

User experience

Mobile app

ICWS mobile application

Lets the user search, confirm location, choose a route, follow directions, and review room information.

Navigation assistant

ABC-chan

Guides the user through destination search, route decisions, floor changes, and arrival.

Relationship: campus Wi-Fi signals may inform positioning; the API and database provide map and destination data; route calculation supplies directions to the mobile application; ABC-chan presents and guides those decisions. NFC readers connect to the college's separate authorised electronic-door access system.

Technology & integrations

Designed around the campus systems it can connect to.

The project specification identifies system components and integrations, but does not select a software stack. Technology choices should be made after reviewing project documentation and campus requirements.

01

Backend and database

A proposed backend API and database can serve approved destination records, indoor maps, route data, and access-related integration points.

02

Indoor positioning and routing

Wi-Fi-based positioning is a proposed input. Route calculation depends on mapped paths, confirmed location, building and floor data, and user route preferences.

03

NFC integration

NFC-compatible door access requires authorised credentials and integration with the college's electronic access-control system. Access decisions remain subject to campus permissions.

04

Project scope and limitations

ICWS is a proposed system. Positioning accuracy, map coverage, route data, device support, accessibility information, and NFC availability depend on future validation and deployment.
